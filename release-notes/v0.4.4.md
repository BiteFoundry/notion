## What's Changed

### Sync & Notion API Latency Optimization
- Replaced chunk-barrier recursive block-tree fetching with a tree-wide `Semaphore(3)` streaming traversal (`buffer_unordered(3)`), eliminating head-of-line blocking while capping nested concurrency safely under Notion's rate limit.
- Overlapped `GET /v1/users/me` with workspace search (`POST /v1/search`) in `run_tree_refresh`, and resolved unresolved `block_id` parent chains in bounded concurrent batches (`chunks(3)`).
- Added cancellable, rate-limit-aware interactive prefetching of up to 2 uncached sibling pages or database rows on focus navigation.

### Write Path & TUI Perceived Latency
- Used cached SQLite database/page schemas first across write operations (`op_create_page`, `op_update_page_metadata`, `op_patch_page`, `op_create_database_item`, `op_update_database_item`) with automatic single refresh-and-retry on HTTP 400 `validation_error`.
- Updated `op_append_blocks` and `op_add_comment` to apply incremental SQLite updates when caches are warm instead of refetching full block trees or paginated comment lists.
- Added instant local previews for newly created pages (`SubmitCreatePage`) and optimistic in-memory appends with failure rollback (`SubmitSlashAppend`), and removed the redundant tree search after `FullResync`.

### Test Hardening
- Guarded unit-test config and draft persistence from mutating the host user config directory and aligned the MCP compact `get_page` hint e2e assertion.

Page JSON reads (`notion pages get --json` and MCP `get_page`) now return compact output by default with `omitted`, `hint`, `incomplete_blocks`, and `comments_state`, without calling `/v1/comments`. Pass `--json --full` (CLI) or `compact: false` (MCP) for the complete page detail.

List commands (`blocks list`, `comments list`, `db list`, `db query`, `pages list`) and their MCP tools now expose `returned`, `has_more`, and `next_cursor` pagination envelopes (`--limit` defaults to 50 for JSON and MCP).

Workspace sync streams every accessible search batch without the 500-object cap, records a completion marker only after a full pass succeeds, and preserves cached batches without advancing the watermark on mid-sync failure. Recursive block loading now traverses 13 levels (depth cap 12) and reports unloaded subtrees in `incomplete_blocks` and stderr warnings.

Offline reads fail explicitly when a page body or comments have never been fetched (or when the last comment fetch failed), and `db query --offline` rejects `--filter` and `--sorts` instead of silently ignoring them. Rollup arrays, rollup date ranges, and `created_by`/`last_edited_by`/`verification` property values are now rendered, and cold-cache search fallback preserves database hits. MCP `content[0].text` now emits minified JSON matching `structuredContent`.

## Compatibility and migration

| Changed output | Before (v0.2.2) | After | Migration for existing callers |
|---|---|---|---|
| `pages get <p> --json` | Full object (`page`, `blocks`, `comments`, `markdown`, `media`) | Compact object (`id`, `title`, `last_edited_time`, `markdown`, `incomplete_blocks`, `comments_state`, `omitted`, `hint`) | Pass `notion pages get <p> --json --full` |
| MCP `get_page` (omitting `compact`) | Full detail | Compact object | Pass `"compact": false` |
| `pages get --json --compact`, MCP `compact: true` | Fetched and cached comments, then omitted them from output | Issues 0 `/v1/comments` requests; reports cached `comments_state` and `omitted.comments` | Run `--full` or `comments list` once when comment cache population is needed |
| `blocks list --json`, `comments list --json`, `db list --json` | Full list | Up to 50 items + `returned`, `has_more`, `next_cursor` | Pass `--limit 100000` or paginate with `--cursor` |
| MCP `get_page_blocks`, `list_comments`, `list_databases` | Full list | Up to 50 items | Pass `"limit": 100000` or paginate with `cursor` |
| `pages get/export --offline` (body not fetched) | Exit 0, empty body | Exit 1 (`HTTP 404` in `serve`) | Read the page online once |
| `comments list --offline` (unfetched or last fetch failed) | Exit 0, `count: 0` | Exit 1 (`HTTP 404` in `serve`) | Read comments online once |
| `db query --offline --filter/--sorts` | Exit 0, filter/sorts ignored | Exit 1 (MCP `isError: true`, HTTP 400) | Drop `--offline`, or drop `--filter`/`--sorts` and filter client-side |
| MCP `content[0].text` | Pretty-printed JSON | Minified JSON | Parse as JSON (equivalent value) |
| `sync` | Stopped at 500 objects | Streams search batches without an object-count cap (verified in loopback mock simulation up to 629 objects across 7 batches; failure recovery verified at 250 and 400 objects); mid-sync failure exits 1 while keeping cached batches | First sync after upgrade enumerates the full workspace once |
| Page detail comments (>2,000 comments) | Silently capped at 2,000 | Serializes at most the first 2,000 comments + `comments_has_more: true` (the 2,001st lookahead entry stays in local cache without refetching until the page changes) | Read all comments with `notion comments list <p> --json --limit 100` and `--cursor` |

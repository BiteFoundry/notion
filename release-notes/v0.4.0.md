Write commands given a page or database title now require a single exact match among active objects (UUIDs and Notion URLs still pass through with zero extra lookups), refusing duplicate titles, partial-title writes, archived targets (except `--unarchive`), and unresolved titles before sending any API mutation. `db update-item` and MCP `update_database_item` now resolve Notion URLs and exact row titles.

Runtime failures under `--json` now emit a structured JSON error object (`{"ok":false,"error":{"code":"...","message":"..."}}`, plus `details.candidates` for ambiguous or missing titles) on stdout while keeping exit code `1` and stderr text. `notion serve` now forwards upstream Notion API HTTP status codes (401, 403, 409, 429, etc.) instead of collapsing them into 500.

`pages edit --title` and `pages create --database` now resolve the target database's actual `title` property name instead of hardcoding `"title"` or `"Name"`, and calling `pages edit <page>` without `--title`, `--icon`, or `--editor` now fails with `invalid_input`. `pages create --body/--file` automatically chunks bodies over 100 blocks, and Markdown conversion now emits Notion `table`/`table_row` blocks and nested list `children` (capped at Notion's two-level single-request limit).

`pages list`, `db list`, and `search` now check the workspace completion marker so partial caches from single-item reads no longer mask the full workspace, and pages edited within the last 90 seconds skip minute-granularity body caching so same-minute updates remain visible on online reads. `db get` exposes `relation_database_id` on relation columns, `notion users list` and MCP `list_users` expose workspace users (20 MCP tools total), and `whoami` prefers the API's `workspace_name` over env-token profile names.

## Compatibility and migration

| Changed behavior | Before (v0.3.0) | After | Migration for existing callers |
|---|---|---|---|
| CLI `--json` runtime failure | Exit 1, stdout 0 B, plain stderr | Exit 1, stdout `{"ok":false,"error":{"code":"...","message":"..."}}` (stderr unchanged); argument errors remain exit 2 with empty stdout | Check exit code or `ok === false` and read `error.code` / `error.message` |
| `pages append --json`, `blocks append --json` | `{ ok, appended, blocks }` (full block objects) | `{ ok, appended, block_ids }` | Pass `--full` with `--json` |
| MCP `append_blocks` (omitting `compact`) | `{ ok, appended, blocks }` | `{ ok, appended, block_ids }` | Pass `"compact": false` |
| `pages export --out <file> --json` | Included full `markdown` in stdout JSON | Omits `markdown` and returns `bytes` (without `--out`, `markdown` is unchanged) | Read the written file at `path` or omit `--out` |
| Title-targeted writes (`pages append/edit/archive/create`, `db create-item/update-item`, `comments add`, MCP equivalents) | First exact or partial match including archived pages; unresolved titles sent raw to API | Active exact title match of exactly 1 object; fails with `ambiguous_page`/`page_not_found` (or database equivalents) | Pass a page/database UUID or Notion URL |
| `pages edit <page>` with no `--title`, `--icon`, or `--editor` | Forced sync and exited 0 | Exit 1 (`error.code: "invalid_input"`) | Pass `--title`, `--icon`, or `--editor` (use `pages get --refresh` to refresh cache) |
